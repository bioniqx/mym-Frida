## Findings

### [MAJOR] frida_env.sh fails under zsh (default macOS shell) and then reports a wrong repository root
- Location: tools/protect/frida_env.sh:15
- Issue: `_script_dir=$(CDPATH='' cd -- "$(dirname -- "${BASH_SOURCE:?must be sourced from bash}")" && pwd) || return 1`. Under zsh `BASH_SOURCE` is unset; the `:?` guard prints the message but does not abort the sourced file, so `dirname -- ""` yields `.` and the script computes `_srcroot` from the *caller's cwd* — observed: it complained `run 'make' at /Users/ethan/Documents first` (two levels too high) and rc=1. If a directory tree matching `…/Documents/build/subprojects/frida-python/frida` ever existed there, the script would silently export a bogus `PYTHONPATH` instead of failing.
- Why it matters: This is contract C6 and the README's documented entry point (`. tools/protect/frida_env.sh`), consumed by S2/S4/S5/S6/S7x/S8. macOS's default shell — and this machine's — is zsh, so the documented usage fails there, with a remediation message pointing at the wrong directory. S1's own criterion ("`python3 -c 'import frida'` succeeds after `. tools/protect/frida_env.sh`") only holds under bash.
- Recommended fix: Make source-path detection portable: use `${BASH_SOURCE:-${(%):-%x}}` under zsh (or `${(%):-%N}`) and fall back to `$0` for POSIX `sh`, then fail fast (before computing any paths) when none is available; alternatively hard-require bash but make the guard actually stop the script and name the real repo root. Add a tiny `test_frida_env.sh` exercising zsh-sourced, bash-sourced, sourced-from-subdir, and missing-build paths.

### [MAJOR] ProtNative.call crashes the JS runtime when an argument is not string-coercible (NULL from JS_ToCString)
- Location: subprojects/frida-gum/bindings/gumjs/gumquickcore.c:1789-1792
- Issue: `op = JS_ToCString (ctx, argv[0]); arg = JS_ToCString (ctx, argv[1]); gum_prot_native_entry (op, arg, out, sizeof (out));` — QuickJS `JS_ToCString` returns NULL when conversion raises (e.g. `ProtNative.call(Symbol(), '')`, or any object whose `toString` throws) or on OOM. `gum_prot_native_entry` then runs `strcmp (op, "ping")` (lib/prot/native_core.c:18) on NULL → segfault in the embedded QuickJS runtime, killing the instrumented process. The glue also ignores `gum_prot_native_entry`'s return code (unknown op silently yields `""`).
- Why it matters: `ProtNative` is a global in every QuickJS agent script (contract C4); any agent or REPL one-liner passing a Symbol or throwing-toString object takes down the target process — a crash bug in exactly the L1 scaffolding that has no test beyond the happy path (script.c:6989 asserts only `('ping','')`).
- Recommended fix: In `gumjs_prot_native_call`, NULL-check `op`/`arg` after conversion (free the other on the early-exit path) and `return JS_EXCEPTION` (the conversion has already set a JS exception) — never call `gum_prot_native_entry` with NULL. Optionally surface a JS error when `gum_prot_native_entry` returns nonzero. Add a QJS-gated test in `tests/gumjs/script.c` asserting `ProtNative.call(Symbol(), '')` throws rather than crashing.

### [MINOR] roundtrip.py mutates the shared build tree and does so non-atomically
- Location: tools/harness/roundtrip.py:60-81 (`_disable_external_helper`)
- Issue: The harness renames every `frida-helper` copy in `build/subprojects/frida-core` to `*.disabled` as a side effect of any compile/run. It is documented and idempotent, but `os.remove(disabled)` + `os.rename` is not atomic: two concurrent harness/tooling processes race (raises `FileNotFoundError`/`FileExistsError`), and the mutation surprises any other local tooling expecting an intact build tree (until the next `make` restores the helper).
- Why it matters: A read-named harness leaving the build tree permanently modified for unrelated work is a footgun in shared worktrees; the race makes parallel gate runs flaky.
- Recommended fix: Guard with an atomic lockfile or `os.rename` first + tolerate `FileExistsError`/`FileNotFoundError`; better, make disabling opt-in via env var with a loud one-time notice.

### [MINOR] _build_entitled_dummy uses predictable /tmp paths and never cleans up
- Location: tools/harness/roundtrip.py:84-110
- Issue: Writes `frida_roundtrip_dummy-<pid>.c`/`.entitlements`/binary into shared `tempfile.gettempdir()` under predictable names and leaves all three behind (only the binary is reused within a process; source and plist are never removed). On a multi-user machine a pre-planted symlink at those paths gets written through (`open(..., "w")` follows symlinks; `clang -o` would clobber the target).
- Why it matters: Classic tmp-predictability hygiene for a tool that also writes+codesigns executables; clutter accumulates per process.
- Recommended fix: Use `tempfile.mkdtemp(prefix="frida-roundtrip-")` per process and clean the directory in an `atexit`/`finally` hook.

### [MINOR] Wrong-key test accepts any exception
- Location: tools/protect/test_encrypt_blob.py:18-27
- Issue: `try: decrypt_blob(container, wrong_key) except Exception: raised = True` — the test would still pass if `decrypt_blob` raised, say, `ValueError` from a magic-check bug instead of `InvalidTag`, masking a real defect in the auth path.
- Why it matters: The wrong-key path is the security-relevant assertion of the suite; it should pin the failure type.
- Recommended fix: `from cryptography.exceptions import InvalidTag` and `except InvalidTag: raised = True` (keeping the key-length `ValueError` assertions as-is).
